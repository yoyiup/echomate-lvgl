# 开发板热点与手机文件传输

## 工作事项

- 在 RV1106 板的 RTL8723BS 上验证 `AP` 模式；现有 `wpa_supplicant` 未编入 AP 功能，SDK 的旧 Realtek 私有接口版 `hostapd` 与板上驱动不兼容，最终用标准 `nl80211` 版 `hostapd` 成功启动。
- 部署 `dnsmasq` DHCP 服务，使手机自动获得 `192.168.50.10–50` 地址。
- 实现轻量 HTTP 页面：手机浏览器上传文件，下载手机上传文件和相机照片、视频。
- 提供 `echomate-hotspot.sh start|stop|status`；关闭热点时恢复原 Wi-Fi 客户端连接。

## 架构与实现原理

单个 `wlan0` 在热点模式下使用 `192.168.50.1/24`。`hostapd` 负责 WPA2-PSK 和 AP 广播，`dnsmasq` 只提供 DHCP，`echomate-transfer` 监听 `192.168.50.1:8080`。热点密码首次启动从 `/dev/urandom` 生成，保存在板子 `/root/.echomate-hotspot-password`（权限 600），不入库。

传输服务为单进程 C++ 程序，避免在 54 MB 内存板上常驻 Python。网页用 `PUT /upload/<文件名>` 发送原始文件内容；服务端按 `Content-Length` 流式写入临时文件，完成后以硬链接发布，避免半个文件被列出或重名覆盖。`GET /download/upload/<文件名>` 下载手机上传文件，`GET /download/camera/<文件名>` 下载 `/tmp/cam` 中的相机文件。文件名解码后拒绝斜杠、控制字符和隐藏文件，下载只读取普通文件并拒绝符号链接。

手机首次测试能上传但不能保存下载。板内下载测试返回完整文件，排查后在响应中加入 `Content-Disposition: attachment`、原始文件名与网页 `download` 属性，并给发送加 30 秒超时；修复后的板内测试使用手机实际上传的 437430 字节照片，HTTP 200、长度一致、附件头与文件名正确。

随后手机反馈第一次下载长时间显示“连接中”，再点一次却很快。用一个已建立但不发请求的空闲 TCP 连接复现：单连接串行服务使第二个请求等待约 **30.13 秒**。文件服务现最多并发处理 6 个连接，每个线程栈限制为 128 KB；空闲连接 3 秒退出，上传正文仍可等待 30 秒。板上用同一张照片及空闲连接复测，下载返回 HTTP 200、437430 字节，开始响应约 **0.028 秒**。这项修复针对浏览器预连接造成的排队，不改变传输文件内容。

手机侧再次刷新并下载，用户确认已能很快完成。

上传保存在 `/tmp/phone_upload`。单文件最多 8 MB，并保留至少 4 MB 的 `/tmp` 空间。`/tmp` 是 tmpfs，重启会清空；`/userdata` 仅约 984 KB 可用，不适合存视频。网页只显示前 100 个文件以限制内存使用。

## 构建与部署

现在也可从 LVGL 主页「手机传文件」或网络页同名按钮开启、关闭热点；页面架构见 [LVGL 手机热点入口](LVGL手机热点入口-2026-11-06.md)。

在仓库 `lvgl_app/tools/hotspot` 目录执行 `sh build.sh`；如 SDK 路径不同，设置 `SDK_ROOT`。脚本从 SDK 复制源码到 `/tmp/echomate-hotspot-build`，交叉编译 `libnl`、标准 `hostapd` 和文件服务，输出四个板端文件与管理脚本。将输出目录的文件复制到板子 `/root/bin/`，然后执行：

```sh
chmod +x /root/bin/echomate-hotspot.sh /root/bin/echomate-transfer
/root/bin/echomate-hotspot.sh start
/root/bin/echomate-hotspot.sh status
```

手机连接状态输出中的 SSID 和密码，再在浏览器打开 `http://192.168.50.1:8080`。关闭热点并恢复家庭 Wi-Fi：

```sh
/root/bin/echomate-hotspot.sh stop
```

## 板上验证

- `iw dev wlan0 info` 显示 SSID `EchoMate-48B4`、`type AP`；`hostapd`、`dnsmasq`、文件服务均常驻。
- 板上 HTTP 自测：首页返回 200；上传返回 201；下载返回 200，内容与上传原文相同。
- 手机实测已连接 `EchoMate-48B4` 并成功打开传输页面。
- 手机上传后板上 `/tmp/phone_upload` 出现约 428 KB 的新文件，主程序与热点服务继续运行。
- 宿主机测试：重复上传同名文件返回 409，不覆盖已有文件。
- 宿主机测试：目录穿越文件名返回 400/413，不读取或写入目录外文件。
- 热点和 LVGL 同时运行时，板子约 32 MB 可用内存；测试文件清理后 `/tmp` 约 26.9 MB 可用。

## 注意事项与后续工作

- 当前是**手动切换模式**，没有开机自动启用。热点打开时原家庭 Wi-Fi 会断开，依赖互联网的天气、语音云服务可能不可用；USB RNDIS 维护连接不受影响。手机可能提示“此网络无互联网”，仍可选择保持连接访问本地地址。
- HTTP 页面通过 WPA2 热点密码控制访问，没有独立网页账号。不要把热点密码公开。
- 录制 AVI/H265 时 `/tmp/cam` 与上传目录共享 27 MB tmpfs；大文件应及时下载到手机或电脑。上传限额与相机录像的 4 MB 余量保护互相配合。
- 手机上传与下载可按网页提示操作；网页访问已由手机侧确认，文件传输的服务端链路经板内自测通过。
- 若需要板子同时连外网并开热点，需另行验证驱动并发模式或增加第二块无线网卡；本实现不假设并发可用。
