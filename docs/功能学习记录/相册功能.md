# 相册功能学习记录

## 目标与范围

新增相册页面，集中查看摄像头页面生成的 BMP 照片、AVI 录像和 H.265/MP4 录像。相册目前展示文件类型、名称、大小、修改时间；点选条目可查看完整路径。刷新按钮重新读取目录。此版本不在开发板上播放照片或视频，也不删除原文件。

## 架构

```text
主页“相册”入口
        │ ui_nav_push
        ▼
ui_gallery.c ── opendir/stat ── /tmp/cam
        │                         ├─ shot_*.bmp
        │                         ├─ video_*.avi
        │                         └─ video_*_h265.mp4
        ▼
LVGL 可滚动文件列表
```

相册是独立 UI 模块，通过 `ui_page_gallery()` 暴露页面构建函数。`ui_theme.c` 注册 `gallery` 调试路由；主页通过统一的 `goto_page_cb` 导航；列表数据只在 LVGL 主线程读取和更新。

## 实现原理

1. 使用 `opendir/readdir` 枚举 `/tmp/cam`，只接收 `.bmp`、`.avi`、`.mp4` 后缀。
2. 使用 `stat` 确认普通文件，并取得字节数和修改时间；不打开媒体内容，所以扫描快、内存占用小。
3. 最多缓存 64 个条目，按修改时间从新到旧排序，再创建可滚动按钮列表。
4. 列表事件仅携带数组下标。点击时检查下标边界，再从静态页面数据中拼接路径，避免事件保存短生命周期局部变量地址。
5. 每次重新打开相册都会刷新；也可点击“刷新”。空目录与目录不可用分别显示提示。

## 注意事项

- `/tmp/cam` 位于 tmpfs，重启会清空；重要照片和录像需及时取回。
- AVI 是未压缩视频，体积增长很快；H.265 MP4 显著节省空间。当前相机模块会对临时录制文件限时，但相册不会自动删除文件。
- `GALLERY_MAX_ITEMS` 限制条目缓存上限，避免意外目录内容造成内存增长；达到上限后只展示扫描到的前 64 个匹配文件。
- UI 文件扫描只在进入/手动刷新时运行，不能放进每帧定时器。
- 文件名来自同一个应用的摄像头模块。目前路径使用固定目录和目录项名称拼接；若未来允许外部写入 `/tmp/cam`，要增加文件名字符校验和符号链接防护。
- 小屏上不创建 BMP 缩略图，也不尝试播放 MP4；全尺寸图像会消耗大量内存与 SPI 刷屏带宽。
