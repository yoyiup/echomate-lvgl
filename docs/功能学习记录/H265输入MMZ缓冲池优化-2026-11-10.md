# H.265 输入 MMZ 缓冲池优化

## 目标

降低 H.265 录像时的 CPU 占用和帧率波动。原实现每帧调用 `RK_MPI_SYS_MmzAlloc_Cached` 和 `RK_MPI_SYS_MmzFree`，内存分配、DMA 缓冲建立与销毁都会产生额外开销。

## 架构

```text
V4L2 MMAP NV12
      |
      | 一次整帧 NV12 拷贝
      v
3 块预分配 DMA MMZ 输入池
      |
      v
RV1106 VENC H.265 硬件编码
      |
      v
H.265 码流 -> MP4 无重编码封装
```

## 实现原理

1. 录像启动时创建包含 3 块缓冲的 DMA MMZ 池，并使用 `bPreAlloc = RK_TRUE` 立即分配。
2. 每帧只用 `RK_MPI_MB_GetMB` 从池里取空闲块，不再创建新 MMZ 块。
3. 摄像头输出为单 plane NV12，Y 后紧跟 UV；用一次整帧 `memcpy` 写入块，刷新缓存后再送给 VENC。
4. `SendFrame` 后释放调用方引用。VENC 保留自己的引用，只有编码器用完后该块才会回到池中。
5. 池暂时没有空闲块时直接丢帧，避免堵住摄像头采集线程和 LVGL。

## 摄像头格式与零拷贝说明

当前摄像头采集明确请求并校验 `V4L2_PIX_FMT_NV12`，是单 plane 布局：前 `width * height` 字节为 Y，后半部为交错 UV。

本次消除了每帧 MMZ 分配/释放，并将 Y/UV 两次复制合并为一次整帧 NV12 拷贝。实现真正零拷贝需要将 V4L2 采集缓冲以 DMA-BUF 导出或改用 Rockit VI，并保证 VENC 释放帧之前不将该缓冲重新 `QBUF` 给摄像头。

## 注意事项

- 不能只预分配一块并每帧立即覆盖：VENC 是异步硬件，上一帧可能仍在读取。
- 预分配 3 块与 VENC 的 `u32StreamBufCnt = 3` 配合，在安全复用和内存占用之间取平衡。
- 使用 cached MMZ 后，CPU 写入结束必须调用 `RK_MPI_SYS_MmzFlushCache`。
- 零拷贝改造要同时处理 DMA-BUF 导入和 V4L2/VENC 所有权，否则会出现花屏或偶发帧损坏。
