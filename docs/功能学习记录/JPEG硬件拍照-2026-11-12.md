# JPEG 硬件拍照（640×480）

## 目标

把摄像头页面原来的未压缩 BMP 拍照改为标准 JPEG：照片固定为
640×480，能被相册和手机传输页面识别，同时降低 `/tmp` 占用和传输时间。

## 架构

```text
SC3336 / ISP
    │ 640×480 NV12
    ▼
V4L2 MMAP 缓冲 ── EXPBUF ──► DMA-BUF fd
    │                              │ dup(fd)，不复制像素
    │                              ▼
    │                       Rockchip MPP / VENC
    │                              │ MJPEG 单帧码流
    │                              ▼
    └── QBUF 归还 ISP       /tmp/cam/shot_XX.jpg
                                      │
                               LVGL 相册 / 手机下载
```

实现文件：

- `src/cam/jpeg_encoder.cpp`：MPP 动态加载、DMA-BUF 导入、单帧 JPEG 输出。
- `src/cam/cam_capture.cpp`：在采集线程收到拍照请求时提交当前 NV12 帧。
- `src/ui/ui_camera.c`：照片扩展名改为 `.jpg`。
- `src/ui/ui_gallery.c`：相册识别 `.jpg/.jpeg`，同时兼容旧 `.bmp`。

## 实现原理

摄像头由 ISP 直接输出 NV12，V4L2 通过 `VIDIOC_EXPBUF` 导出同一块物理
缓冲的 DMA-BUF fd。拍照时只 `dup` 这个 fd 后交给 MPP：`dup` 只复制文件
描述符引用，不复制 460800 字节的图像，因此输入仍为零拷贝。

MPP 使用 `MPP_VIDEO_CodingMJPEG`，输入格式为 `MPP_FMT_YUV420SP`，质量因子
固定为 90。编码后的单帧码流本身就是完整 JPEG 文件，不需要 MP4/AVI 这类
视频容器；写入 `.jpg` 后可由浏览器、相册和 FFmpeg 直接解码。

MPP 输出仍位于 DMA-BUF 环形缓冲。代码按 `offset + len` 是否跨越缓冲尾部
拆成两段写文件，避免把跨尾数据误当成从 0 开始的连续数据。

## RV1106 特别注意事项

1. `mpp_buffer_import_with_tag()` 会接管传入 fd，并在 `buffer_put()` 时关闭。
   不能直接传 V4L2 原始 fd，否则四个采集缓冲会逐个失效；必须传 `dup(fd)`。
2. 导入的 `MppBuffer` 必须保留到 `encode_get_packet()` 返回之后，才能把当前
   V4L2 缓冲 QBUF 给 ISP，避免硬件尚未读完时画面被下一帧覆盖。
3. 这版 RV1106 内核驱动对单帧 JPEG 也执行码控检查。必须设置 FIXQP，并把
   输入/输出 fps 的分子、分母设为有效值。分母为默认值 0 会触发内核断言。
4. 输出等待限制为 3 秒。编码器异常时拍照会失败并显示原因，不允许采集线程
   永久卡在 `encode_get_packet()`。
5. MPP 运行库和 `/dev/mpi/venc` 由 `/root/bin/load_h265.sh` 统一准备。脚本名
   保留了历史命名，但加载的是共用 VENC 环境，也供 JPEG 使用。
6. 拍照只允许在 640×480 采集模式执行。1280×960 是 H.265 录像专用模式，
   UI 会禁用拍照；底层也再次校验尺寸，防止未来界面改动绕过约束。

## 2026-11-12 板端实测

实拍文件 `/tmp/cam/shot_00.jpg` 为 12747 字节。电脑侧 `file` 识别为
`JFIF 1.02, baseline, 640x480, components 3`；`ffprobe` 识别为
`mjpeg / 640x480 / yuvj420p`；下面的完整解码检查无任何错误：

```sh
ffmpeg -v error -xerror -i shot_00.jpg -frames:v 1 -f null -
```

同分辨率 24 位 BMP 的固定大小约为 921654 字节，本次 JPEG 比 BMP 小约
98.6%。测试结束后已去掉 `CAM_PHOTO_AUTOTEST` 和 `LVGL_START_PAGE` 环境，
恢复 `/root/bin/lvgl_daemon.sh` 正常守护启动，应用进程持续运行。
