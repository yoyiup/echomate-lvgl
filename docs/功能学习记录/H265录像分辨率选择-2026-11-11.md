# H.265录像分辨率选择（2026-11-11）

## 功能目标

摄像头页面为H.265/MP4录像增加两档原生采集分辨率：

- 640×480：默认档，内存和CPU压力较低。
- 1280×960：高清档，保留更多细节。

屏幕预览仍固定为320×160，页面尺寸和LVGL canvas内存不变。

## 界面设计

摄像头页面底部新增分辨率按钮：

```text
[拍照] [AVI] [H265] [640/1280]
```

点击按钮会停止当前摄像头、设置下一次V4L2采集尺寸并自动重启。录像期间按钮禁用，防止编码中途改变输入尺寸。

1280档仅用于H.265：拍照和AVI按钮会暂时禁用。切回640后恢复，确保原有BMP和未压缩AVI仍保持640×480，避免1280×960 AVI以约29.5MB/s迅速耗尽内存盘。

离开摄像头页面时自动恢复640×480，避免YOLO或其他页面下一次启动摄像头时误用1280×960，造成额外转换和内存压力。

## 数据路径

```text
分辨率按钮
    │
    ├─ cam_stop()
    ├─ cam_set_capture_size(640×480 / 1280×960)
    └─ 页面轮询自动cam_start()
             │
SC3336 → RKISP原生NV12
             ├─ 抽样/居中裁剪 → 320×160 RGB565预览
             └─ DMA-BUF零拷贝 → MPP H.265 → MP4
```

通过 `v4l2-ctl` 验证，`/dev/video11` 的NV12支持32×16至2304×1296、步长8，因此1280×960是ISP原生输出，不是把640×480软件放大。

## 实现原理

### 可切换采集尺寸

`CamCapture` 增加 `requested_w_ / requested_h_`。停止状态下调用 `cam_set_capture_size()`，下一次 `VIDIOC_S_FMT` 使用请求尺寸；驱动最终返回的尺寸仍写回 `cap_w_ / cap_h_`，上层不假设驱动一定接受。

接口只接受640×480和1280×960，运行中切换返回忙状态，避免采集线程仍在使用旧缓冲时改变格式。

### 预览

1280×960 NV12一帧为：

```text
1280 × 960 × 3 / 2 = 1843200字节
```

4个V4L2缓冲约7.03MB。预览转换按4倍步长抽样，并从4:3源画面中间裁出2:1的320×160画面，不增加canvas大小。

### H.265码率与内存

- 640×480：目标2.048Mbps。
- 1280×960：目标封顶4.096Mbps。

如果完全按像素数线性放大，1280×960会达到8.192Mbps。10秒录像在封装时raw和MP4短暂双份，可能占约20MB，而 `/tmp` 只有27MB并与系统共享RAM。因此高清档封顶4.096Mbps，使最坏情况下的临时双份约10MB，并继续保留12MB系统安全余量。

## 板端验证

- 驱动实际接受：NV12 1280×960。
- 每个DMA-BUF：1843200字节，共4个。
- rkaiq成功prepare 1280×960，3A正常。
- H.265硬编码：1280×960、30fps。
- 2秒录像：64帧，约803.5KB，实测码率约3.08Mbps。
- FFmpeg `-v error -xerror` 严格逐帧解码通过，无POC、NAL或参考帧错误。
- 分辨率按钮实测可在640×480和1280×960之间来回切换，应用持续存活。
- 320×240界面抓图确认4个按钮均完整显示，无重叠。

## 注意事项

1. 1280×960时4个采集缓冲比640×480多约5.27MB，和YOLO、热点并发时要继续观察MemAvailable。
2. 高清档预览仍为320×160；屏幕看起来不会更大，提升体现在保存的视频细节。
3. 高分辨率下整机CPU瞬时采样可达约80%，稳定后约43%；摄像头与编码仍保持30fps。
4. 不要在录像中切换尺寸；界面已禁用按钮，底层接口也会拒绝。
5. 不要开放1280×960未压缩AVI，单帧约3.52MB，8fps约28.1MB/s，板端不具备持续存储条件。
6. `CAM_H265_RES=1280x960` 是板端自动回归开关，正常守护程序不设置，默认仍为640×480。
